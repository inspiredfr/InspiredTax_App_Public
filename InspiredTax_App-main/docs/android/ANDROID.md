# Android packaging runbook (Capacitor)

The repo carries a complete Capacitor Android wrap. The web app is the single-file
artifact; `www/index.html` is a generated copy of it (gitignored). The native
project in `android/` is committed (Capacitor convention — native customisations
are source).

## Layout

| Piece | Where | Notes |
|---|---|---|
| Capacitor config | `capacitor.config.json` | appId `za.co.inspiredtax.app` (change before first Play upload if desired — it is permanent once published), `webDir: www`, `androidScheme: https` (keeps `crypto.subtle` in a secure context) |
| Web dir producer | `tools/make-www.js` | `npm run www` = build artifact + copy to `www/index.html` |
| Sync | `npm run cap:sync` | `npm run www` + `npx cap sync android` (copies web assets + plugin manifests) |
| Native project | `android/` | Generated by `npx cap add android`, committed |
| Plugins | `@capacitor/app` (back button + minimize), `@capacitor/filesystem` + `@capacitor/share` (exports via share sheet) | Registered automatically by `cap sync`; the web code accesses them via `window.Capacitor.Plugins.*` — no web-side imports |
| Custom plugins | `PlayBillingPlugin`, `TrialAnchorPlugin`, `CloudBackupPlugin` (+ shared base `GoogleDrivePlugin`) in `android/app/src/main/java/za/co/inspiredtax/app/` | Registered in `MainActivity.java`. Dumb I/O pipes — all logic is JS. Contracts: `docs/programmes/monetization/02-BILLING-PLUGIN.md`, `04-TRIAL-ANCHOR.md`, and the header of `src/js/17-cloud-backup.js` (checked by `tests/cloud-backup.js`). Dependencies: Play Billing 8.0.0, play-services-auth 22.0.0 (`AuthorizationClient`; the legacy `GoogleSignIn` API is gone — BACKLOG 75, DECISIONS AUTH-2) |
| SDK levels | `android/variables.gradle` | min 24, compile/target 36 (2026-10-04) |

## In-app native integrations (already implemented in `src/`)

- **Back button**: `initBackNavigation()` (02-core) registers `App.backButton`;
  `backAction()` routes one contextual close per press (modal → drawer → panel →
  `App.minimizeApp()`).
- **Exports**: `_downloadBlob()` (02-core) writes to the app cache via
  `Filesystem.writeFile` and opens the Android **share sheet** (`Share.share`)
  on native; browser anchor-download otherwise. Every export (JSON backup, CSV,
  ITR12 text, a closed year) routes through it. It returns a promise of the
  outcome — `'shared'`, `'cancelled'` (sheet dismissed: nothing saved) or
  `'downloaded'` (browser) — and rejects on a failed write or share; callers
  confirm success only after it resolves (BACKLOG 72, 2026-10-14).
- **Import**: `<input type="file">` — Capacitor's `BridgeWebChromeClient`
  implements the file chooser natively. Verify on device (§QA).
- **Keyboard**: the Capacitor template default `android:windowSoftInputMode=
  "adjustResize"` is correct for the app's fixed bottom sheets; the viewport
  meta also carries `interactive-widget=resizes-content`. Do NOT add the
  `@capacitor/keyboard` plugin resize modes — its `resize` config is iOS-only
  and the Android default already behaves correctly.
- **Local backup snapshot for Android Auto Backup** (owner decision
  2026-07-11 — Option A, not a custom Google Drive API integration):
  `writeLocalBackupSnapshot()` (02-core) writes the same PIN-encrypted
  envelope as a manual "Export JSON" backup to `Directory.Data` (=
  `context.filesDir`) on every lock (`_lockApp()`), via `Filesystem.
  writeFile`. This app makes no network call of its own for this — Android's
  OS-level Backup Manager (`android:allowBackup="true"`) is what
  opportunistically syncs the snapshot to the device's signed-in Google
  account, independent of this app's own permissions/process, roughly daily
  when idle+charging+Wi-Fi. Backup scope is deliberately narrowed to just
  this one file (both `android/app/src/main/res/xml/backup_rules.xml` for
  API < 31 and `data_extraction_rules.xml` for API 31+) — the WebView's own
  storage is excluded by simply not being listed. `getLastLocalBackupAt()`
  reads the file's own mtime for the Backup modal's status line
  (`renderLocalBackupStatus()`), which says "on this device only" — since
  OD-41 (2026-09-10) the UI makes no claim about OS sync it cannot verify.
  Restore from the OS backup is entirely OS-managed. App-managed Drive backup
  (Option B) is now built separately as cloud backup, switched off — see
  `BACKLOG.md` item 11.

## Build (owner machine — needs Android Studio / SDK; not possible in the sandbox)

**One-time per machine** (both files are gitignored — machine-specific, they
never come from git, so a fresh clone won't have them):

- `android/local.properties` — points Gradle at your Android SDK. Create it
  with **forward slashes**:
  ```properties
  sdk.dir=C:/Users/You/AppData/Local/Android/Sdk
  ```
  (Path is shown in Android Studio under Settings → Languages & Frameworks →
  Android SDK. Without this file the build fails with *"SDK location not
  found"*.)
- `android/app/keystore.properties` — signing config; see § Signing below.
  Forward slashes there too (a backslash path throws *"Malformed \uxxxx
  encoding"*).

**Every build:**

```bash
npm ci                    # if dependencies changed
npm run cap:sync          # build.js + make-www.js → www/ → android/
npx cap open android      # opens Android Studio
# Build > Generate Signed App Bundle (.aab) for Play; or Run on a device for QA
```

⚠ Use `npm run cap:sync`, **not** `npx cap sync` directly — the npm script
builds the `www/` web-assets dir first (via `tools/make-www.js`), which raw
`npx cap sync` does not, so it fails with *"Could not find the web assets
directory: www"*.

⚠ Do **not** run `git clean -fd` in this repo to "reset" — it deletes the two
gitignored machine files above (`local.properties`, `keystore.properties`),
which then have to be recreated by hand. Use `git checkout -- <path>` or
`git reset --hard` to discard tracked changes instead.

Icons/splash: the launcher, adaptive, monochrome and notification icons in
`android/app/src/main/res/` were imported from the brand package on
2026-07-18 (#151); the source files and their map are in `assets/branding/`
(`README.txt`). `assets/icon*.png` are the older 2026-07-14 sources. Since
BACKLOG 73 (2026-10-14) the adaptive foreground and monochrome layers and
every `drawable*/splash.png` are generated by `tools/make-android-icons.py`
(Python 3 + Pillow, dev-only): the glyph fits inside the 66 dp safe circle,
both layers share one centred geometry, and the splash is the R on brand
navy, which `values/splash.xml` also sets as the Android 12+ splash
background.

## Signing (owner machine — needs a JDK `keytool`; keystore never touches the sandbox)

**Incident, 2026-07-15 → 2026-07-18**: a real `keystore.properties` was once
committed to `main` via GitHub's web "Add files via upload" UI, which
bypasses `.gitignore` entirely (a file already tracked isn't retroactively
protected by an ignore rule added later — only `git rm --cached` does that).
Remediated by rotating to a brand-new keystore and untracking the file
(#154). The release workflow now pins the upload certificate's SHA-256
(`.github/workflows/build-inspiredtax.yml`, `EXPECTED_UPLOAD_CERT_SHA256`). **Lesson**: never add
`keystore.properties` — or any secrets file — via a GitHub web upload, a
Claude session, or any path that doesn't go through the normal gitignored
local-file workflow below.

The pattern below is the one to follow when generating a keystore — no real
keystore/passwords should ever be pasted into a Claude session, uploaded
through the GitHub web UI, or committed to git in any form.

### 1. Generate the upload keystore (one-time)

```bash
keytool -genkeypair -v -keystore upload-keystore.jks -alias inspiredtax \
  -keyalg RSA -keysize 2048 -validity 9125
```

`-validity 9125` = 25 years (Play requires the key to be valid past 2033).
`keytool` will prompt for a keystore password, a key password, and
distinguished-name fields (org, city, country — use `ZA`) — any values are
fine, they aren't shown to users.

**This is an upload key, not the app-signing key** — during the first release
in Play Console, enroll in **Play App Signing**: Google holds the real
app-signing key, this upload key just authenticates uploads to Google. That
makes losing this specific key recoverable (Google can re-issue upload-key
rotation via a signed request) — but treat it as irreplaceable anyway, since
key-rotation support requires proving prior ownership and has its own delays.

**Back up `upload-keystore.jks` and its passwords in 2+ places** (e.g. a
password manager entry with the file attached, plus an offline/cold copy) the
same day it's generated. Losing it *before* Play App Signing enrollment means
the app can never be updated again under the same package name — there is no
recovery path in that case.

### 2. `keystore.properties` (gitignored — lives only on the signing machine)

Create `android/app/keystore.properties` (already covered by
`android/.gitignore` — `app/keystore.properties`, `*.jks`, `*.keystore`):

```properties
storeFile=/absolute/path/to/upload-keystore.jks
storePassword=<keystore password>
keyAlias=inspiredtax
keyPassword=<key password>
```

Never commit this file, never paste its contents into an issue/PR/chat. Each
machine that produces signed release builds needs its own copy, sourced from
the backed-up keystore in step 1. `android/app/keystore.properties.example`
has the same template committed as a starting point — copy it, don't edit
it in place.

### 3. `signingConfigs` in `android/app/build.gradle` (already wired)

`android/app/build.gradle` already reads `app/keystore.properties` and wires
a guarded `signingConfigs.release` — nothing to edit here, just drop the
properties file from step 2 in place:

```gradle
def keystorePropertiesFile = rootProject.file("app/keystore.properties")
def keystoreProperties = new Properties()
if (keystorePropertiesFile.exists()) {
    keystoreProperties.load(new FileInputStream(keystorePropertiesFile))
}

android {
    ...
    signingConfigs {
        release {
            if (keystorePropertiesFile.exists()) {
                storeFile file(keystoreProperties['storeFile'])
                storePassword keystoreProperties['storePassword']
                keyAlias keystoreProperties['keyAlias']
                keyPassword keystoreProperties['keyPassword']
            }
        }
    }
    buildTypes {
        release {
            signingConfig keystorePropertiesFile.exists() ? signingConfigs.release : null
            minifyEnabled true
            shrinkResources true
            proguardFiles getDefaultProguardFile('proguard-android-optimize.txt'), 'proguard-rules.pro'
        }
    }
}
```

The `keystorePropertiesFile.exists()` guard means the project still builds
(unsigned) on a machine without the properties file — e.g. CI running lint
only — instead of failing the Gradle sync.

### 4. Build and verify

```bash
npm run cap:sync
cd android && ./gradlew bundleRelease   # or Android Studio: Build > Generate Signed App Bundle
```

Output: `android/app/build/outputs/bundle/release/app-release.aab`. Confirm
it's actually signed: `jarsigner -verify -verbose -certs app-release.aab`
should report `jar verified`. Install the matching `.apk`
(`./gradlew assembleRelease`) on a real device and run the full Device QA
checklist below — this is also the point where R8/Proguard-related crashes
(if any) would surface, since debug builds skip minification.

## Device QA checklist (before any Play upload)

General regression on a real device. Feature-specific device checks owed by
recent changes are in `docs/android/DEVICE-CHECKS.md`.

1. **Back button/gesture**: closes wizard modals step-free, closes drawer,
   returns to Dashboard, then minimizes (never kills mid-entry). Onboarding:
   steps back, exits only from step 1.
2. **Exports**: Profile → Export JSON / Export CSV and Tax screen → ITR12
   export each open the share sheet; the shared file opens correctly.
3. **Import**: Profile → Import opens the system file picker; a previously
   exported JSON restores.
4. **Offline**: airplane mode → icons, brand fonts and charts all render
   (all assets are vendored; the WebView code makes no network request — only
   the native billing, trial-anchor and cloud-backup plugins do).
5. **Keyboard**: bottom-sheet wizards — focused inputs stay above the soft
   keyboard at every step; `enterkeyhint` shows Done on PIN fields.
6. **Safe areas**: notch/punch-hole devices and gesture nav — header, bottom
   nav, FAB and sheets clear the insets (portrait; landscape is not a target
   but must not crash).
7. **Deep state**: background the app 5+ min → PIN lock screen returns;
   unlock restores state.
8. **TalkBack pass**: navigate the dashboard and one wizard end-to-end.

## Version bumps

Never by hand: `npm run release:bump` (or the *Build InspiredTax* workflow)
moves `package.json`, `build.gradle` `versionCode`/`versionName`, `STATUS.md`
and `CHANGELOG.md` together — see `RELEASE.md`. `versionCode` =
maj·10000 + min·100 + patch.
